# `reflect`: отчёт о работе агента

[← Оглавление](README.md) · [README](../../README.ru.md) · [English](../reflect.md) · **Русский**

`echolot analyze` стоит между трейсом и агентом. `echolot reflect` стоит
между сессией агента и разработчиком инструмента. Причина та же: транскрипт
сессии весит от сотен килобайт до десятков мегабайт, и читать его вручную —
человеком или моделью — долго, дорого и невоспроизводимо. Поэтому транскрипт
детерминированно сжимается в таблицу фактов и короткий список сигналов, и
решение «что менять» принимается по ним.

```bash
cd ~/StudioProjects/my-app        # проект, в котором работал агент
echolot reflect --list            # подходящие сессии
echolot reflect --last            # последняя, использовавшая echolot
echolot reflect --session 3f2a    # одна сессия по префиксу id
echolot reflect --since 2h        # все сессии за последние 2h / 30m / 3d
echolot reflect --all             # все, плюс сводка summary
```

Вывод: `.echolot/reflect/<session>.md` для человека, `.json` для агента —
`/echolot-reflect` читает json и превращает сигналы в список предлагаемых
правок. Если в прогон попадает больше одной сессии (`--all` или `--since`),
рядом пишутся `summary.md` и `summary.json`: строка на сессию и частота
каждого сигнала, чтобы повторяющиеся проблемы инструмента сразу бросались в
глаза.

Где ищутся данные по умолчанию и как это переопределить:

| флаг | по умолчанию | что задаёт |
|---|---|---|
| `--project ROOT` | `.` | проект приложения, где работал агент — журнал запусков, конфиг, исходники |
| `--transcripts DIR` | `~/.claude/projects/<slug>` | каталог транскриптов Claude Code; явное указание отключает чтение сессий Codex |
| `-c`, `--local` | копия, которую команды самой сессии читали через `-c`, если она одна; иначе `echolot.yml` в проекте; `local.yml` рядом | конфиг, по которому проверяются правила протокола; если он изменился после сессии, заголовок отчёта говорит об этом |
| `-o DIR` | `.echolot/reflect` в проекте | куда писать отчёты; путь, заданный явно, считается от текущей папки, как у `-c` |
| `--from-log` | выкл | игнорировать транскрипты и читать только журнал запусков — см. ниже |

## Два источника

**Собственный журнал инструмента.** Каждая команда дописывает строку в
`.echolot/log/runs.jsonl`: аргументы (`argv`), место, время, код возврата,
длительность, хэш конфига, traceback при падении и несколько фактов (сколько
детекторов сработало, совпал ли якорь, что закрыло launch-окно). Этот
источник не зависит от агента и не теряет код возврата при обёртывании в
`2>&1 | tail`. Отключается через `ECHOLOT_NO_RECORD=1`.

**Транскрипт Claude Code.** Хранится в `~/.claude/projects/<slug>/`
(субагенты — в `<session>/subagents/`). Содержит то, чего не видит CLI:
промпты, вопросы человеку и ответы, каждый вызов инструментов, токены, бриф
для `perf-hunter` и его ответ. Неожиданные поля попадают в «Reader notes», а
не вызывают падение.

**Сессии Codex.** Хранятся в
`~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<thread id>.jsonl` (или под
`CODEX_HOME`). Субагенты пишутся отдельными файлами с указанием родителя в
первой строке. Поскольку бриф субагента в Codex хранится на диске
зашифрованным, проверка `agent_prompt_gaps` помечается как непроверенная с
указанием причины, вместо того чтобы считать бриф пустым.

`reflect` читает сессии Claude Code и Codex вместе (от новых к старым) и
отбирает только те, где `echolot` реально применялся, игнорируя сессии,
которые только запускали сам `reflect`.

## Что входит в отчёт

Сначала сигналы, затем факты, на которых они основаны:

| раздел | что содержит | зачем нужен |
|---|---|---|
| Signals | нарушения протокола (`warn`), обходные пути и трение (`info`) с подсказками | что менять и в каком порядке |
| Protocol checks passed | проверки со статусом `ok` | чтобы короткий список Signals читался как чистота, а не отсутствие проверок |
| Not checked | пропущенные проверки (`skip`) и причины | какие молчания не являются вердиктом |
| Entry | промпты, slash-команды, загруженные скиллы, время до начала работы | понятен ли вход в инструмент |
| Timeline | ключевые вехи по времени | куда ушло время |
| echolot calls | каждый вызов: подкоманда, аргументы, выход, длительность, размер вывода, справки | на каких командах агент спотыкается |
| Questions to the human | каждый `AskUserQuestion`: варианты, рекомендованный, выбранный, время ответа | нужны ли вопросы и верны ли умолчания |
| What the main context concluded | финальное сообщение (`conclusion` в json) | к чему пришла сессия |
| Subagent | раунды относительно `loop.max_rounds`, перезаписи, инструменты, токены, бриф и поля вывода | как вёл себя цикл поиска |
| Temporary instrumentation | по файлам: добавлено/удалено маркеров, `grep` после правки, остаток в коде | убраны ли маркеры |
| Cost | настенное время, токены отдельно для главного контекста и субагентов, крупнейшие выводы | что съедает окно |
| Recorder | строки `runs.jsonl` внутри окна сессии | коды возврата, потерянные транскриптом |

Не включается в отчёт: текст рассуждений (только подсчитывается), полные
выводы инструментов и длинные промпты (усекаются). Отчёты лежат в
`.echolot/`, который в `.gitignore`.

## Сигналы — это детекторы

Как и в `echolot/sql/detectors/`, один сигнал — это функция в
`echolot/reflect/signals.py` поверх нормализованной сессии. Добавив функцию
в `SIGNALS`, нужно решить два вопроса через allowlist-ы: может ли она
работать только по логу вызовов (`FROM_CALLS_ALONE`) и имеет ли она смысл в
сессии разработки самого инструмента (`MEANS_SOMETHING_WHILE_BUILDING`).
Пока сигнал не добавлен туда, в соответствующих режимах он уходит в **Not
checked**.

Группы сигналов:

- **entry** — `entry_fumbling`, `agent_prompt_gaps`
- **protocol** — `doctor` до `analyze` (в самой сессии или успешный в журнале
  запусков не раньше чем за 24 часа до него, как его показывает `echolot`); запрет прямого чтения трейса; цикл
  внутри субагента; гайды цикла оставлены субагенту; лимит раундов; префикс
  временных вызовов; правки только в `instrumentation.allowed`; очистка
  временных маркеров (приоритетно проверяется по реальному дереву файлов); 8
  полей вывода; анализ по конфигу проекта; калибровка перед правкой порогов;
  сохранение базовых трейсов перед перезаписью; неизменность подтверждённых
  человеком значений
- **workarounds** — ручной разбор `report.json`; `--help`/`explain` в
  середине работы; прямой запуск gradle/adb/perfetto вместо `collect`;
  `agent_reported_bugs` (цитаты агента на английском или русском о багах в
  echolot)
- **failures** — ошибки вызовов `echolot`, traceback-и, ошибки shell,
  повторные попытки, ошибки прочих инструментов
- **cost** — паузы от двух минут, выводы > 8К символов, чтение исходников
  вручную вместо отчёта

Отклонения инструментов самой средой (отказ в песочнице или отмена
пользователем) не считаются падениями `echolot` и учитываются отдельно в
`env_friction`.

## Что инструмент честно не видит

`instrumentation.allowed` контролирует только временное инструментирование
субагента и строки с префиксом, а не финальный фикс пользователя в главном
контексте. Раунды считаются по транскрипту (`collect` + `analyze` открывают
новый раунд). Несколько вызовов в одной строке shell делят один код возврата
и время на строку, о чём отчёт явно предупреждает.

## Без транскрипта

Для Claude Code и Codex есть собственные парсеры. Любой другой клиент,
обычный shell или CI получают отчёт только по журналу
`.echolot/log/runs.jsonl`:

```bash
echolot reflect --last              # сам откатывается к логу и сообщает об этом
echolot reflect --last --from-log   # принудительно читать только лог
```

Проверки по вызовам (`FROM_CALLS_ALONE`: `doctor_first`, `confirmed_changed`,
`echolot_failures`, `retries`, `help_lookups`, `long_gaps`) работают как
обычно; всё, что требует транскрипта (`Session.carries`), честно уходит в
**Not checked**, чтобы отсутствие данных никогда не выдавалось за «нарушений
не найдено». Поскольку в `runs.jsonl` нет ID сессии, запуски делятся на
сеансы по паузам более получаса.

## Сессия разработки самого инструмента

Если рабочий каталог — сам репозиторий `echolot` (по `pyproject.toml`), и в
сессии не запускались `collect` или `hunt`, протокольные правила охоты
автоматически уходят в **Not checked**, а активными остаются только проверки
трения (`MEANS_SOMETHING_WHILE_BUILDING`): падения, повторы, длинные паузы и
большие выводы.

## Транскрипт другого агента

Вся аналитика в `reflect` работает поверх нормализованной модели из
`echolot/reflect/model.py`. Поддержка нового клиента сводится к написанию
ридера, заполняющего эту модель и объявляющего доступные поля в
`Session.carries`.
