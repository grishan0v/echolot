# Приватность

[← Оглавление](README.md) · [README](../../README.ru.md) · [English](../privacy.md) · **Русский**

echolot работает на вашей машине и хранит всё созданное там же. У него нет
учётных записей, собственного сервера и телеметрии, и он ничего никуда не
отправляет: ни трейсы, ни отчёты, ни счётчики запусков. Плагин для Claude Code,
Codex и Cursor — это просто текст: четыре скилла, которые подсказывают агенту,
какую команду `echolot` запустить следующей.

На этой странице перечислено всё, что CLI читает, записывает и скачивает. Сеть
используется только в двух местах — оба раза это загрузки, и каждая из них
проверяется перед использованием.

## Что инструмент читает

- **Проект.** `echolot.yml`, а также файлы сборки и исходный код, которые
  сканирует `setup` и на которые `analyze` ссылается в находках.
- **Телефон**, через `adb`: трейсы, которые `collect` снимает с приложения, и
  состояние устройства, от которого зависит серия повторов — включён ли экран
  и что показывает датчик температуры. При включённом `runner.compose_names`
  он также запрашивает у приложения версию библиотеки трассировки, а у
  телефона — архитектуру CPU.
- **Файлы сессий самого агента**, только для `echolot-reflect` (`echolot
  reflect`), локально с этой машины: сессии Claude Code в
  `~/.claude/projects/`, сессии Codex в `~/.codex/sessions/` и собственный
  журнал запусков echolot — `.echolot/log/runs.jsonl`. Они читаются локально,
  и ничто из них не покидает машину; результаты анализа сохраняются в
  `.echolot/reflect/`.
- **Настройки агентов**, чтобы `echolot`, `status` и `doctor` могли проверить,
  установлен ли плагин и правило Codex:
  `~/.claude/plugins/installed_plugins.json` и `~/.claude/settings.json`,
  копия в `~/.cursor/plugins/local/echolot`, а также `~/.codex/config.toml` и
  `~/.codex/rules/`.
- **Кэш Gradle**, при включённом `runner.compose_names` — для библиотеки
  `tracing-perfetto-binary`, если проект уже собирался раньше.

## Что инструмент записывает

Внутри проекта:

- `echolot.yml`, который создаёт `setup`;
- `.echolot/`: трейсы, отчёты, выводы `reflect` и журнал запусков. В журнале
  хранится по одной строке на команду: какая команда, когда, как долго
  работала, код возврата и несколько замеченных фактов. Переменная
  `ECHOLOT_NO_RECORD=1` отключает запись;
- несколько строк в `.gitignore` или, при запуске `init --private`, в
  `.git/info/exclude` самого репозитория;
- файлы для выбранных вами агентов при `echolot init`: слой `.claude/`, блок
  между маркерами `<!-- echolot -->` в `AGENTS.md`, `GEMINI.md` или
  `.github/copilot-instructions.md`, `.cursor/rules/echolot.mdc`, а для Codex
  — `.codex/rules/echolot.rules`, выпускающий `echolot` из песочницы;
- на время расследования — временные маркеры трассировки в исходниках,
  разрешённых в `instrumentation.allowed`. Команда `echolot mark --remove`
  удаляет их.

Вне проекта:

- `~/.local/share/perfetto/prebuilts/`, где после скачивания хранится
  `trace_processor`, и пустой lock-файл во временной директории системы,
  чтобы две одновременные загрузки не мешали друг другу;
- `~/.cache/echolot/` (или `$XDG_CACHE_HOME/echolot`) при включённом
  `runner.compose_names`: библиотека трассировки;
- `~/.cursor/plugins/local/echolot` — только при явном запуске `echolot plugin
  cursor`.

На телефоне `collect` пишет в один файл
`/data/misc/perfetto-traces/echolot.pftrace` и скачивает его в проект;
следующий повтор перезаписывает его. Настройки, которые `runner:` меняет на
время серии (режим полёта, яркость экрана, режим производительности),
возвращаются в исходное состояние по окончании серии. При включённом
`runner.compose_names` `collect` копирует библиотеку трассировки в
медиа-каталог самого приложения и удаляет её после серии.

## Что инструмент скачивает

Две загрузки, по одному разу на версию:

- **`trace_processor`**, программа, читающая трейсы. Сборка, зафиксированная
  Python-пакетом `perfetto`, из хранилища артефактов Perfetto
  (`commondatastorage.googleapis.com/perfetto-luci-artifacts`), с проверкой
  SHA-256 по манифесту пакета. Занимает 10–14 МБ при первом запуске команды,
  которой она нужна. Флаг `--tp-binary` или ключ `toolchain.tp_binary` в
  `local.yml` позволяет указать собственный бинарный файл — тогда ничего не
  скачивается. Подробнее — в разделе [Загрузка](determinism.md#загрузка).
- **`tracing-perfetto-binary`**, только при включённом
  `runner.compose_names`: библиотека, включающая трассировку в приложении в
  той версии, которую оно запрашивает. Берётся из кэша Gradle, если она там
  есть, иначе — из Google Maven (`dl.google.com/android/maven2`) с проверкой
  SHA-1. Приложение дополнительно проверяет её по контрольным суммам своей
  версии.

Установка выполняется вами отдельно: `pipx install echolot` скачивает пакет с
PyPI, Claude Code и Codex загружают плагин из
[этого репозитория](https://github.com/grishan0v/echolot) по тегу релиза, а
`echolot plugin cursor` копирует его для Cursor из уже установленного пакета.

## Что инструмент отправляет

Ничего. Нет ни телеметрии, ни отчётов о сбоях, ни проверок обновлений.

Два сетевых соединения остаются внутри машины: `perfetto` запускает
`trace_processor` и общается с ним по HTTP через `localhost`, а `adb` общается
со своим сервером на `localhost:5037`, который подключается к телефону по USB
или локальной сети.

`echolot ui` открывает третье локальное соединение на время своей работы:
сервер на `127.0.0.1`, отображающий состояние проекта в браузере. Он не
слушает никакие другие адреса, отвечает только на запросы с токеном текущего
запуска, отдаёт только сгенерированные страницы без доступа к файлам и не
обращается ни к каким внешним адресам. Подробнее об ограничениях — в
[Страница в браузере](ui.md#на-что-сервер-отвечает-и-в-чём-отказывает).

Запущенный вами агент читает вывод `echolot` и передаёт его своей модели в
рамках сессии. Этот трафик относится к самому агенту и регулируется условиями
его провайдера.
