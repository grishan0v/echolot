# Страница в браузере

[← Оглавление](README.md) · [README](../../README.ru.md) · [English](../ui.md) · **Русский**

`echolot` показывает состояние проекта в терминале для тех, кто привык к
терминалу. `echolot ui` показывает то же самое в браузере: готовность
окружения, кнопку для проверки приложения, а также отчёты и ответы агента —
каждый в виде отдельной страницы. В проекте без конфига он сначала создаст
конфиг для запуска приложения. Со страницы отчёта он может запустить ваш
собственный Claude Code на отмеченных проверках и показывать его работу по ходу
дела.

```bash
echolot ui              # запускает сервер и открывает браузер
echolot ui --no-open    # печатает адрес, не открывая браузер
echolot ui --port 8123  # на конкретном порту вместо свободного
```

Сервер работает до нажатия Ctrl-C. Запускайте из каталога проекта, где лежит
или будет лежать `echolot.yml`; флаг `-c` задаёт путь к конфигу в другом
месте.

Веб-страница — это интерфейс для человека поверх тех же команд и файлов. Она
заново считывает состояние проекта при каждом открытии, с одним исключением:
то, что `echolot scan` прочитал в репозитории, сервер помнит между страницами,
пока прочитанные файлы не изменились (см. [стартовую страницу](#стартовая-страница)).
Основной путь для агента остаётся в командной строке.

## Настройка проекта

В проекте без `echolot.yml` стартовая страница спрашивает **What do you want
to check?** (Что вы хотите проверить?) и предлагает один вариант: **How the
app opens** (Как открывается приложение) — от нажатия на иконку до первого
экрана. Это единственный сценарий, который не нужно описывать: его окно — сам
запуск по записи телефона
([`scenario.window: launch`](analysing.md#окно-равное-запуску)), а
`echolot scan` составляет весь конфиг по файлам сборки. Приложение, которое
открывается на заставке и само переходит к основному экрану, меряется до
первого кадра основного экрана, а первая строка отчёта говорит, где был кадр
заставки: «The launch takes 0.7 s. It runs past SplashActivity's first frame
at 0.2 s: the app went on to MainActivity by itself, and the start was not
over.»

Кнопка **Set it up** сохраняет этот черновик в `echolot.yml` — тот же текст,
который `echolot scan` печатает под «A config to start from», с двумя
строками комментария сверху. Если echolot ещё не настраивался в этом
проекте, также запускается `echolot init`: файлы для агента, строки в
`.gitignore` и самопроверка компьютера (занимает около минуты). Эта часть идёт
фоновым процессом рядом с сервером, так что страница показывает прогресс и
затем сама переходит к кнопке запуска проверки.

Перед нажатием страница показывает две вещи:

**Чьё это приложение**: идентификатор пакета, под которым ставится
приложение, и измеряемая сборка (как их прочитал `scan`). Именно это
страница просит подтвердить, потому что разработчик узнаёт эти имена, а
нажатие кнопки служит подтверждением. В файл не записывается пометка
`_source: confirmed_by_user`: каждое значение сохраняет пометку `scan` и его
обоснование — вы посмотрели два имени, а не паттерн процесса и параметры
раннера, так что позже агент сможет поправить их, если ошибся.

**Что будет записано**, под спойлером: каждый файл с назначением и полный
текст конфига. Все файлы новые, кроме `.gitignore` или вашего
`.claude/settings.json`, куда лишь дописываются строки. `echolot.yml`
создаётся только если его нет: если он появился между открытием страницы и
нажатием кнопки, действие останавливается и ничего не перезаписывается.

**Лимит времени** задаётся строкой с полем «It should take no longer than …
seconds» (от 0.1 до 60). Это необязательно; значение записывается в
`scenario.budget_ms` в миллисекундах. С лимитом первая строка отчёта сразу
говорит, уложилось ли открытие приложения в бюджет. Без него сообщается лишь
длительность запуска с уровнем «not checked».

Лимит — это одна строка файла под окном сценария, с комментарием от самой
страницы; если лимит не задан, та же строка стоит закомментированной. Обычно
нужное число становится понятно только после первого отчёта, где написано «No
time limit is set», поэтому страница может задать или поменять лимит и позже —
в этой же строке или в строке лимита любого `echolot.yml`: см.
[Лимит времени после настройки](#лимит-времени-после-настройки).

**Всё остальное** (конкретный экран или действие) настраивается через агента:
ему нужно изучить код и понять, как туда попасть и где начинать/заканчивать
ожидание. Страница прямо пишет об этом под кнопкой и даёт готовую команду для
копирования.

**Если страница не может настроить проект**, она объясняет причину своими
словами, приводит вывод `echolot scan` и отправляет к разделу **What to do
next**:

| что нашёл `scan` | что говорит страница |
|---|---|
| нет модуля с launcher Activity | в этом каталоге нет Android-приложения |
| `applicationId` или суффикс измеряемой сборки заданы так, что `scan` их не читает (константу или элемент enum в `buildSrc` и `build-logic` он читает) | не удалось прочитать имя приложения из файлов сборки |

Макроbenchmark запуска (`StartupTimingMetric`) настраивается так же, как
приложение без бенчмарка: то же окно `launch`, запускаемое через benchmark.
Если макроbenchmark измеряет собственный участок или неизвестную метрику,
начало и конец его окна нужно выбрать по пробной записи, поэтому страница
настраивает запуск приложения, как для проекта без бенчмарка: echolot сам
открывает приложение (`runner.mode: launch`). Строка рядом с именем
приложения называет бенчмарк и говорит, что агент может настроить его потом.

Некоторые шаги всегда идут раньше: файлы от более новой версии echolot,
проваленный self-check или `echolot init` в проекте с устаревшими файлами или
уже выбранными агентами. В этих случаях `init` обновляет файлы сам и
показывает, что именно обновил, поэтому шаг остаётся командой для терминала;
после его выполнения страница предложит настроить конфиг. Сервер, запущенный с
флагом `-c` на нестандартный файл, автоматическую настройку не делает.

**Конфиг без сценария** измеряет всё содержимое записи. Страница показывает
готовые строки для `window: launch`, чтобы добавить их вручную, и не трогает
ваш файл.

**После настройки** страница показывает кнопку проверки. Пока сценарий ещё ни
разу не записывался, она напоминает, что измеряемая сборка должна быть на
телефоне (в режиме `launch` echolot открывает уже установленное приложение и
сам ничего не собирает), называет задачу Gradle для установки (если её удалось
найти) и показывает статус подключения телефона в блоке **Ready**.

**Если настройка прервалась**, `echolot.yml` к этому моменту уже записан.
При ошибке `echolot init` страница показывает хвост вывода и путь к полному
логу; при обрыве (остановка `echolot ui`, закрытие терминала) — сообщает об
этом. Дальше шаг из **What to do next** подхватывает с того же места.

### Лимит времени после настройки

То же предложение с полем, «It should take no longer than … seconds», стоит
рядом с вердиктом отчёта на странице и в **All settings › Time limit**; в
поле уже стоит действующий лимит, а под ним — строка `echolot.yml`, которую
поменяет нажатие. Кнопка **Set the limit** записывает число, а пустое поле
снимает лимит.

Можно ли странице менять файл, решает его содержимое, а не то, кто его
написал: конфиг, написанный руками, `echolot scan` или агентом, получает поле
так же, как записанный самой страницей, и каждый сценарий конфига с
несколькими сценариями тоже (отчёт сценария задаёт лимит этого сценария).
Нажатие меняет ровно одну строку `echolot.yml` или добавляет одну:

- в строке `budget_ms` под сценарием меняется число, а всё остальное в ней
  остаётся, включая ваш комментарий и пробелы. Пустое поле превращает строку
  в комментарий, `# budget_ms: 500`, а следующее нажатие с числом возвращает
  её. Строку, которую записала сама страница, она и пишет так, как пишет
  всегда, с обновлёнными секундами в комментарии;
- закомментированный `budget_ms` под сценарием — та же строка: нажатие
  убирает `#`;
- если у сценария нет `budget_ms` вовсе, страница добавляет свою строку
  первым ключом сценария, с тем же отступом, что у его ключей;
- в сценарии, записанном в одну строку, `{name: coldStart, budget_ms: 500}`,
  меняется число; снять такой лимит страница не может и так и говорит.

Всё остальное в файле остаётся байт в байт как было, включая ваши
комментарии, пустые строки и порядок ключей. Новый файл сначала пишется
рядом со старым, перечитывается (он должен говорить то же, что и раньше, с
одним изменённым лимитом, для всех сценариев), читается так же, как его
читает любая команда, и только потом встаёт на место старого, поэтому никто
не прочитает файл наполовину записанным.

Страница ничего не меняет, одной фразой объясняет почему и называет строку,
которую можно поправить руками, если:

- сценарий записан в одну строку и лимита в нём нет, или лимит — не число на
  своей строке: на строке под ключом или взят из якоря в другом месте;
- лимит задан в `local.yml` рядом, а он сильнее `echolot.yml`;
- `echolot.yml` — ссылка на другой файл или у него есть второе имя, он не
  читается, или `echolot ui` запущен с `-c` и читает другой файл;
- файл изменился между открытием страницы и нажатием. Страница помнит, какой
  файл она вам показала, и нажатие, которое застаёт другой, ничего не пишет.
  Одно и то же нажатие, отправленное дважды, считается одним.

`analyze` берёт лимит в тот момент, когда читает трейсы, поэтому после
изменения отчёт остаётся прежним, сделанным со старым лимитом. Страница так и
пишет и предлагает **Read the recordings again**: то же чтение уже
записанных трейсов, что и у кнопки проверки, — без телефона и без сравнения
после него, ведь трейсы те же самые. Вердикт поменяется, когда будет записан
новый отчёт; сама страница ничего не вычисляет.

У отчёта, сохранённого на диск командой `analyze --html`, поля нет: файл не
может поменять конфиг.

## Проверка приложения

Одна кнопка записывает приложение, анализирует трейсы и открывает отчёт.
Запускаются ровно те же команды CLI, поэтому результат идентичен терминалу:

```bash
echolot collect -c echolot.yml -n 3
echolot analyze .echolot/traces/coldStart_iter*.perfetto-trace -c echolot.yml --html
```

Подпись рядом с кнопкой заранее объясняет, что произойдёт: сколько запусков,
сколько примерно времени займёт и что код проекта не изменится. В режиме
`gradle` количество итераций задаёт сам макроbenchmark, о чём страница
предупреждает.

**Когда запуск невозможен**, кнопка отключена, а подпись объясняет почему:

| что мешает | что говорит подпись |
|---|---|
| нет телефона, их несколько или не разрешена отладка | строка телефона из **Ready** целиком: ошибка, с которой останавливается `collect`, и что сделать |
| приложение нельзя профилировать или есть только debuggable-сборки | то же сообщение из строки приложения |
| проект не настроен, конфиг не читается или страница не может [настроить проект](#настройка-проекта) | сначала нужно выполнить шаг из **What to do next** |
| настройка ещё не завершилась | echolot проверяет этот компьютер, кнопка появится после завершения |
| последний self-check не прошёл | доверять отчётам на этой машине нельзя |
| открыто расследование | с записями сейчас работает агент, сначала нужен его ответ |
| запись уже идёт (из терминала или от агента) | что именно запущено, на каком этапе, и предложение подождать |

Даже если запрос на запуск дойдёт до сервера, он перепроверит состояние
проекта в этот момент и вернёт ту же причину отказа.

**Во время прогона** место кнопки занимает **Stop** и пошаговый список: по
строке на каждый запуск, затем анализ записей и, при наличии предыдущего
отчёта, сравнение. Все строки видны сразу, чтобы понимать прогресс. Можно
наблюдать за телефоном: приложение само открывается и закрывается.

Состояние прогона страница читает из двух файлов, ничего не храня в памяти
сервера: `.echolot/log/check.json` и `.echolot/log/collect.json`.
Перезагрузка страницы, вторая вкладка и даже перезапущенный `echolot ui`
покажут тот же прогресс.

**Stop** останавливает запись, сохраняет уже снятые трейсы и не запускает
анализ. Команде посылается сигнал завершения, как по Ctrl-C, так что настройки
телефона возвращаются обратно. Страница сообщает, сколько записей
сохранилось.

**Одновременно идёт только одна проверка.** Повторное нажатие (в том числе из
другой вкладки) ничего не запускает и показывает текущий процесс.

**Завершение прогона** отображается отдельным итогом:

| исход | что показывает страница |
|---|---|
| завершён | «Done. The short version:», число проверок каждого уровня, кнопки **See the report** и **Check again** |
| остановлен | сколько записей сохранено |
| ошибка | на каком шаге упало и что сохранено; точная команда для терминала, хвост вывода и путь к полному логу |
| прерван извне (`echolot ui` закрыт, сон компьютера) | сообщение о прерывании и что сохранено; зависший процесс никогда не рисуется как «идёт» |

Ctrl-C в терминале `echolot ui` завершает активную проверку так же, как
**Stop**, и при следующем старте страница покажет, что прогон был прерван.

Последний итог держится на стартовой странице, пока это самое свежее событие
(максимум сутки). Как только появится новая запись или отчёт, либо пройдут
сутки, страница возвращается к обычному виду состояния проекта.

**Check again** появляется, когда уже есть отчёт. Кнопка повторяет прогон и
сравнивает новый отчёт с предыдущим:

```bash
echolot compare .echolot/out/before.json -c echolot.yml --html
```

Так как `analyze` перезаписывает последний отчёт, перед этим он копируется в
`before.json` рядом. Результаты сравнения (`comparison.md`, `comparison.json`,
`comparison.html`) остаются лежать рядом с отчётом. Стартовая страница
показывает итог словами из [простого чтения](compare.md#простое-чтение) и
кнопку **See what changed**, ведущую на вкладку **After the fix**.

**Уже имеющиеся записи** читаются без телефона: если для сценария есть
трейсы новее отчёта (или без отчёта), появляется кнопка **Read the
recordings**, запускающая только `analyze`, а рядом — **Record again**. Записи
из сторонней папки тоже читаются со страницы: см. [ниже](#записи-сделанные-в-другом-месте).

### Записи, сделанные в другом месте

Артефакт CI, который кто-то скачал, выходная папка макробенчмарка, запись от
коллеги: **Analyse trace files**, складка под кнопкой, читает их без телефона.
Впишите папку, где они лежат, путём на этом компьютере
(`~/Downloads/benchmark-results`, путь от папки проекта или полный) и нажмите
**Look in this folder**. Браузер не может передать локальному серверу путь
через поле выбора файла, только сами байты, поэтому поле текстовое.

Просмотр ничего не читает. Следующий экран говорит, что лежит в папке, по
именам файлов:

| что лежит | что говорит экран |
|---|---|
| записи с именами от `collect`, `coldStart_iter002.perfetto-trace` | сколько их у сценария `coldStart`, какого объёма, насколько свежие и есть ли такой сценарий в конфиге |
| записи макробенчмарка, `StartupBenchmark_startup_iter002_2026-11-20-140212.perfetto-trace` (или `.trace`) | то же для теста `StartupBenchmark_startup`; если номер итерации повторяется, это сказано: в папке несколько прогонов, и один отчёт по всем смешает их в одну медиану |
| имена, по которым сценарий не понять | сколько их, под **Names that say no scenario** |
| несколько таких групп | по карточке на каждую, чтобы выбрать одну: отчёт — про один сценарий |
| в папке записей нет, но есть во вложенных | по кнопке на каждую такую папку; кнопка смотрит в неё |
| папки нет, файл — не запись, папку нельзя открыть | об этом, и поле снова |

Запись — файл, имя которого кончается на `.perfetto-trace`, `.pftrace` или
`.trace`, в самой папке; одну запись можно указать и саму по себе.

**Read them** запускает `analyze` по выбранным записям, как это делает
кнопка, поэтому отчёт тот же, что дал бы терминал:

```bash
echolot analyze ~/Downloads/ci/coldStart_iter*.perfetto-trace -c echolot.yml --html -o .echolot/out/elsewhere
```

Записи становятся **отдельным отчётом** в `.echolot/out/elsewhere`, а не
отчётом сценария. Чужие записи, прочитанные как отчёт вашего сценария,
встали бы рядом с прогонами этого телефона в следующем сравнении: отчёты
сценариев и то, с чем сравнивает **Check again**, остаются прежними. Следующая
прочитанная папка займёт его место. Сценарий конфига задаёт только окно, с
которым читаются записи; если сценариев несколько, его выбирают на экране
(по умолчанию тот, что назван в именах), и он передаётся через `--scenario`.

Чтение — такой же прогон, как у кнопки: по одному за раз, **Stop**
останавливает его, стартовая страница показывает строку прогона и его итог —
«Done. The short version: 4 recordings from `~/Downloads/ci`, read as a report
of their own», — а **See the report** открывает отчёт. В **Reports** он стоит
после отчётов сценариев, с указанием, откуда записи. Чтение отклоняется по тем
же причинам, что и кнопка (открыто расследование, идёт запись, проект не
настроен), и если выбранных записей в папке больше нет.

**Несколько сценариев** в конфиге отображаются в виде переключаемых карточек
со статусом каждого. Выбранный сценарий передаётся командам через `--scenario`.

**Число запусков** для кнопки настраивается под **All settings** (от 1 до
20). Сначала там `runner.iterations` из конфига: столько записывает `echolot
collect` в терминале и **Check again** на странице расследования (5, если в
конфиге ничего нет; 3, если там не целое число). Три прогона работают быстро и
уже показывают разброс; для уверенного сравнения нужно четыре с каждой
стороны или три против пяти. Параметр передаётся в `collect` через `-n` и
ничего не пишет в `echolot.yml`. Там же в **All settings** перечислены точные
команды, которые запустит кнопка, с числом из поля.

**Без JavaScript** в браузере всё работает: кнопка запуска и Stop — это
обычные HTML-формы, а страница прогона сама обновляется каждые несколько
секунд. При включённом JS список обновляется на месте раз в секунду, а
подписи реагируют на выбор сценария и числа запусков.

## Стартовая страница

**Ready** — три строки с цветными индикаторами:

| строка | зелёный | красный | серый |
|---|---|---|---|
| Этот компьютер | последний self-check прошёл | последний self-check упал: запустите `echolot doctor` | self-check ещё ни разу не запускался |
| Телефон | найденное для `collect` устройство (модель) | нет устройств, их несколько или не разрешена отладка | |
| Приложение | запись увидит приложение, и указана сборка | нет `<profileable android:shell="true" />` или только debuggable-сборки | конфиг называет пакет, но его кода нет в этой папке |

Красный статус указывает на блокер и даёт способ его устранить. Серый — то,
что отсюда проверить нельзя; он ничего не блокирует. **Refresh** перечитывает
всё заново.

**Репозиторий читается один раз, а не на каждой странице.** То, что страница
говорит о приложении, его сборках и бенчмарке, берётся из `echolot scan`, а на
репозитории в миллион строк `scan` тратит секунды процессорного времени на
свободной машине и больше минуты на загруженной. Поэтому сервер помнит
прочитанное вместе со слепком файлов и читает репозиторий снова на следующей
странице, если:

- изменился, появился или исчез build-скрипт, `settings.gradle(.kts)`, каталог
  версий или манифест;
- изменился файл build-кода (`buildSrc` и сборки, которые подключают settings);
- изменился исходник модуля с бенчмарком;
- где угодно появился или исчез исходный файл.

Правка исходника в любом другом модуле репозиторий заново не читает: от неё
ничего из сказанного `scan` не зависит. Слепок — это один обход дерева и `stat`
тех файлов, что учитываются; константа, которую бенчмарк берёт из файла другого
модуля, в него не входит, и **Refresh** перечитывает репозиторий тоже. В **All
settings** страница пишет, когда репозиторий читался в последний раз. Телефон
спрашивается на каждой странице, как и раньше: он появляется и пропадает без
изменения файлов.

**What to do next** появляется, когда следующий шаг не сводится к кнопке
проверки или [автонастройке](#настройка-проекта): `echolot doctor`, `echolot
init` или команда агента для сложной настройки или продолжения расследования.

**Reports** выводит последний отчёт каждого сценария с его уровнем, первой
строкой, временем и числом срабатываний, а затем — историю всех расследований.
Каждый отчёт открывается как [веб-страница отчёта](analysing.md#отчёт-как-веб-страница),
рендерясь прямо из `report.json` на лету; битый файл не делается ссылкой и
помечается ошибкой чтения.

## Остальные страницы

Верхняя панель — навигация по этапам: **Start**, **Report**, **Agent's
answer**, **After the fix**. Вкладка появляется, как только для неё есть
данные.

- **Report** — последний отчёт выбранного на старте сценария.
- **Agent's answer** — новейшее расследование в виде
  [веб-страницы](agent-layer.md#ответ-агента-в-виде-страницы) (та же, что
  пишет `echolot hunt --show --html`), отрисованная по текущему `hunt.json` и
  приложенным отчётам.
- Каждое более раннее расследование открывается по первой ссылке в своей
  строке на стартовой странице.
- **After the fix** — [страница сравнения](compare.md#сравнение-в-виде-страницы)
  последнего отчёта с предыдущим. Появляется, только если сравнение относится
  к текущему отчёту на вкладке **Report** и содержит `plain`-чтение (от
  `compare --html` или `compare --plain`).

На странице ответа агента кнопка **Check again** стоит рядом с командой
перепроверки и запускает её целиком: `collect`, `analyze` и `compare` против
первого отчёта расследования (состояния приложения до правок). Прогон виден
на стартовой странице, и там строка сравнения и фраза под прогоном называют
этот отчёт: «Comparing with round 1 of investigation #5», «It was compared
with round 1 of investigation #5». Нажатие на стартовой странице сравнивает
с предыдущим отчётом и так и говорит.

**All settings** — сворачиваемый блок с числом запусков, полными командами и
технической сводкой: конфиг, сборка, `runner.mode`, окно, лимит `budget_ms`
(с полем, которое его задаёт или меняет, если лимит стоит в файле на своей
строке, кто бы файл ни написал, а иначе — с причиной и строкой для правки),
источники порогов каждого
детектора, версии echolot и `trace_processor`, а также сырой вывод `echolot`
и `echolot hunt --list`.

## Агент со страницы

Отчёт говорит, что медленно; агент находит, где это в коде и что поменять. На
странице отчёта отметьте проверки, с которых начать, и нажмите **Dig deeper**.
Кнопка рядом сама отмечает, с чего начать: проверки, которым нужно внимание, а
если таких нет — две, нашедшие самое крупное. Одно расследование отвечает на
один вопрос, поэтому запрос
([так его собирает отчёт](analysing.md#отчёт-как-веб-страница)) начинается с
одного вопроса, несёт предупреждения отчёта и перечисляет отмеченные строки
как то, на чём этот вопрос стоит. Если отмечено больше трёх проверок, страница
говорит, что одно расследование смотрит на один вопрос, и советует отметить
не больше трёх; кнопка, которая отмечает, с чего начать, больше трёх не
отмечает: если внимание нужно больше чем трём проверкам, она берёт три,
нашедшие самое крупное.

Если рядом с отчётом лежит сравнение именно этого отчёта, оставленное
`echolot compare` (`comparison.json`, чья новая сторона — этот отчёт), то
запрос, который экран перед запуском даёт скопировать, и запрос, который
получает агент, несут то, что сравнение нашло хуже: строки, новые в каждом
запуске этого отчёта, и строки, которые выросли и держатся
([Holds](compare.md#столбец-holds)), в порядке сравнения, не больше восьми,
каждая с пометкой `new in 5 of 5 runs` или `grew for sure`. Они идут после
предупреждений отчёта и перед его строками. Сравнение другого отчёта (двух
файлов, названных вручную, или сделанное до последнего `analyze`) ничего не
добавляет, как и сравнение, которое говорит, что две стороны сравнивать
нельзя; если пороги двух сторон разные, «новая» строка ничего не значит и не
попадает в запрос, как и маркер, поставленный расследованием под префиксом
из конфига.

В окне запроса есть **Copy the request** — чтобы вставить его в своего агента,
и, если страница может запустить агента сама, **Start it from here**. Своей
модели у echolot нет: запускается Claude Code или Codex, установленный на этом
компьютере, под вашей учётной записью. Кнопка появляется, когда Claude Code
установлен, его версия 2.1.259 или новее и он сообщает, что вход выполнен
(`claude auth status`), или когда установлен Codex версии 0.159 или новее,
вход выполнен (`codex login status`) и в проекте есть то, что ему нужно
([ниже](#с-codex)); иначе окно говорит, чего не хватает каждому из
установленных, и запрос остаётся для копирования. Если один может
запуститься, а другой установлен и не может, окно и экран перед запуском
говорят, почему не может он: например, каких правил не хватает Codex и что их
пишет `echolot init --for …,codex`. Cursor со страницы пока не запускается: его
запрос копируется.

**Какой `echolot` запускает агент.** Агент запускает `echolot` через свою
оболочку, и какой это `echolot`, зависит от вашей оболочки, а не от страницы:
Codex выполняет каждую команду в login-оболочке (`zsh -lc`), а Claude Code — из
снимка login-оболочки, которая сначала прочитала `~/.zshrc` (или `~/.bashrc`).
Профиль, который ставит первой в `PATH` другую папку, например со старым
echolot из pipx в `~/.local/bin`, заставил бы расследование идти на другом
echolot, чем страница, которая его потом читает. Поэтому страница ставит свою
папку первой в `PATH` агента, а экран перед запуском спрашивает оболочку
клиента — так, как клиент выполняет команду, и с тем же окружением, — какой
`echolot` она находит. Если это другой echolot другой версии или такой, что не
называет версию, экран называет его и echolot страницы, советует поставить
папку страницы первой в `PATH` оболочки или удалить другой и не предлагает
**Start**; нажатие отклоняется так же. Другая установка той же версии работает
как echolot страницы. Окно на странице отчёта этого не спрашивает, как не
спрашивает и телефон.

Любому агенту нужна папка, куда ставить маркеры: если в
`instrumentation.allowed` нет ни одной, страница не запускает никого. Тогда в
окне нет **Start it from here**, и оно говорит об этом один раз: где назвать
папки (`echolot.yml`, под `instrumentation:`) и как
(`allowed: ["app/src/main", "feature/*/src/main"]`); ни один экран не
предлагает одного агента вместо другого. В `echolot.yml`, который пишет
**Set it up**, названы папки, где `scan` нашёл код приложения.

**Пока ничего не запущено**, один экран простыми словами говорит, на что вы
соглашаетесь нажатием **Start**:

- **Кто работает**: Claude Code, его версия и учётная запись, под которой
  выполнен вход. Он тратит то же, что любая ваша сессия, — ваш тариф Claude
  или ваш API-ключ — и сам останавливается, когда по его собственной оценке
  потратил около $10.
- **Сколько времени**: обычно десятки минут. `echolot ui` должен работать, а
  телефон — оставаться подключённым и разблокированным: если закрыть
  `echolot ui`, агент тоже остановится.
- **Что он делает**: ставит временные маркеры в папки из
  `instrumentation.allowed`, пересобирает приложение, ставит его на телефон и
  записывает снова, не больше `loop.max_rounds` раундов; в конце убирает
  маркеры и записывает ответ.
- **Что можно без спроса**, точный список: `echolot` (любая команда),
  `./gradlew` (любая задача), `adb` (любая команда на телефоне), правка файлов
  в разрешённых папках и запись `.echolot/verdict.json`. Читать файлы проекта и
  запускать команды, которые только читают, он тоже может. Всё остальное
  отклоняется без вопроса кому-либо: git, загрузки, любые другие программы,
  любые другие файлы. Вопрос, который он хочет вам задать, отклоняется так же,
  и он продолжает с тем, что есть. Разрешения из `.claude/settings.json`
  самого проекта тоже действуют, и экран называет те, что сверх правил
  echolot.
- **Что изменится**: код на диске, пока он работает, и ничего не коммитится
  (экран говорит, сколько файлов уже изменено); на телефоне остаётся сборка с
  маркерами, пока приложение не пересоберут; Claude Code хранит свою запись
  сессии, как и для любой сессии.
- **Stop**: останавливает Claude Code и всё, что он запустил.

На том же экране — две команды, которые будут запущены, и запрос целиком, а
**Copy the request** остаётся выходом. Нажатие **Start** запускает их одну за
другой в папке проекта:

```text
echolot hunt "<the question>" --since unknown
claude -p "<the request>" --output-format json --permission-mode dontAsk --permission-prompts none --setting-sources project --max-budget-usd 10 --allowedTools "Bash(echolot *)" "Bash(./gradlew *)" "Bash(adb *)" "Edit(/app/src/main/**)" "Edit(/.echolot/verdict.json)"
```

Обе строки сервер собирает из конфига и отчёта на диске; из того, что прислал
браузер, в них не попадает ничего: нажатие называет отмеченные проверки, и они
сверяются с отчётом в эту минуту. На каждую запись `instrumentation.allowed`
приходится одно правило `Edit(…)`; если список пуст, страница ничего не
запускает. Разрешения не обходятся: `dontAsk` отклоняет всё, что не разрешено
правилом, `--permission-prompts none` отклоняет вопрос, на который некому
ответить, а `--setting-sources project` оставляет в стороне ваши личные
настройки, хуки и плагины и подключает команды проекта для Claude Code,
которые ставит `echolot init`. Запрос говорит агенту, что за клавиатурой никого
нет, какое расследование для него открыто (каждый `collect` и `analyze` идёт в
него с `--hunt <n>`) и на каких трейсах, что ему можно и что закончить нужно
вердиктом.

**Пока агент работает**, браузер открыт на странице его расследования. Раунды
появляются как обычно (каждый отчёт, который он сохраняет), а над ними строка
говорит, что агент делает сейчас. Страница видит это по программам, которые он
запустил, и не читает того, что он печатает: сборка приложения, установка на
телефон, запись, чтение трейсов, установка маркеров, просмотр расследования,
запись ответа (только пока агент закрывает расследование) или, если ничего из
этого, чтение кода и раздумья. Если около десяти минут ничего не
меняется (ни раунда, ни сборки, ни записи), страница говорит об этом рядом с
**Stop**. Сборка может идти так долго, и тогда страница называет её.

**Stop** отправляет Ctrl-C самому Claude Code и всему, что он запустил, как это
делает терминал с целой задачей: запись спокойно завершается и возвращает
настройки телефона. Что осталось через 30 секунд, завершается, а затем
останавливается принудительно. После этого страница считает то же, что `hunt`:
сколько временных маркеров осталось в коде, сколько из них уберёт
`echolot mark --remove` и в каких файлах маркеры добавлены вручную. Строку с
`// echolot:mark`, на которой есть что-то кроме маркера, например однострочный
`try { work() } finally { android.os.Trace.endSection() }`, который агент
написал сам, `--remove` не трогает. Страница называет файл и номер каждой такой
строки, чтобы убрать маркер вручную, и не пишет, что код чист, пока такая
строка есть.
**Take the markers out** запускает `echolot mark --remove`; на телефоне маркеры
остаются, пока приложение не пересоберут и не поставят заново.

**Чем это может закончиться**:

- закрыто с вердиктом: страница расследования и есть ответ, с одной тихой
  строкой о том, сколько он работал и сколько, по словам Claude Code,
  потратил;
- закрыто несколькими словами без вердикта: эти слова стоят заголовком
  страницы;
- остановлено: страница говорит об этом и о том, что осталось в коде;
- достигнут лимит трат: «It reached the spending cap of $10» и сколько, по
  словам Claude Code, он потратил — его оценка может немного перейти лимит;
- ошибка: «Claude Code stopped with an error» с его собственными словами
  (истёк вход, кончился лимит тарифа) и путём к полному журналу;
- прервано, когда `echolot ui` остановили или компьютер уснул: так и сказано;
- закончил, не записав ответа: так и сказано, с его последними словами.

Если агент сам не закрыл расследование, оно остаётся открытым, и **Check the
app** ждёт, пока оно открыто: **Close the investigation** закрывает его с тем,
к чему оно пришло (`echolot hunt --done "Stopped from echolot ui, after 2 rounds, with no answer. …"`).
Эти слова становятся заголовком страницы, а строка о том, как агент закончил,
говорит, что расследование потом закрыли со страницы: «It ended before it had
an answer, and the investigation was closed from this page after that».
Что расследование закрыл агент, она говорит, только если он сам закрыл его,
пока работал; закрытое вручную после его конца — «closed after that».
Что агент пытался сделать и получил отказ — в списке в конце: каждая команда
одной строкой, первой, и сказано, важно ли это. Каждый отказ стоил ему хода, а
запуску без ответа могли отказать в шаге, который был нужен.

### С Codex

Codex запускается так же, с того же экрана, и отличается в четырёх вещах: где
лежит то, что ему разрешено, что он может править, что он делает, когда
некому ответить, и что он сообщает в конце.

**Который из двух.** Если запуститься могут оба, экран перед запуском
показывает один, а **Use Codex instead** (или **Use Claude Code instead**)
ведёт на экран другого. Каждый экран говорит, что можно его собственному
агенту, и **Start** запускает того, чей это экран. Первым показан тот, кого
использовал последний запуск со страницы, а если такого не было — Claude Code:
его собственные правила держат правки в разрешённых папках.

**Что нужно проекту**: git-репозиторий — Codex просит его, чтобы его
изменения можно было увидеть и отменить; отсутствие отметки `untrusted` для
проекта в ваших настройках Codex; и `.codex/rules/echolot.rules` в том виде, в
каком его пишет этот echolot, с правилами, которые выпускают `echolot`,
`./gradlew` и `adb` из песочницы Codex
([песочница без сети](agent-layer.md#песочница-без-сети)). Этот файл пишет
`echolot init --for …,codex`. Про файл, который записал echolot постарше,
только с правилом для `echolot`, страница говорит, что он старый, и называет
`init`, который его обновит.

**Что его экран говорит сверх того, что говорит экран Claude Code**:

- Codex отмечает проект как доверенный в ваших собственных настройках,
  `~/.codex/config.toml`, как делает это, когда впервые работает в проекте.
  Это изменение вне проекта, и оно остаётся; если файл уже доверяет проекту,
  экран так и говорит.
- Его правки нельзя ограничить разрешёнными папками, поэтому страница
  запоминает файлы проекта перед запуском и после показывает те, что
  изменились вне этих папок.
- Лимита трат нет: страница показывает токены, которые Codex сообщит в конце.
- Если 30 минут ничего не меняется, страница его останавливает.
- Ваши собственные файлы правил, которые Codex тоже читает, в `.codex/rules/`
  и `~/.codex/rules/`, названы: то, что они разрешают, тоже действует.

```text
echolot hunt "<the question>" --since unknown
codex exec --json -s workspace-write -C /path/to/the/project "<the request>"
```

В режиме `exec` Codex ничего не спрашивает. Команда идёт в его песочнице, где
нет сети и писать можно только внутри проекта, а команда, которую выпускает
правило, идёт вне её. Ни один флаг не обходит его подтверждения или песочницу.
Запрос тот же, и факты в нём слово в слово, вместе с `--hunt <n>`; только
вместо строк для Claude Code в нём строки для Codex: что `/echolot-hunt` —
команда Claude Code, а те же шаги печатает `echolot guide hunt`, и что правило
выпускает команду, только когда в строке она одна, без конвейера и `&&`.

**Когда некому ответить.** Задав вопрос, на который некому ответить, Codex
принимает его и ждёт — часами. Запрос говорит, что ответить некому. Через
десять минут без движения страница говорит об этом, как и для Claude Code, и
добавляет, что через полчаса остановит Codex. Через 30 минут без единого
события, нового раунда и программы под ним страница завершает его так же, как
**Stop**, говорит почему и показывает вопрос, ответа на который он ждал, как
его последние слова. Программы, которые ваши собственные настройки Codex
запускают вместе с ним, например MCP-серверы, тоже считаются его
собственными: они работают всё время и ничего не сообщают. Долгая сборка или
запись — это то, что работает, и так никогда не завершается; не завершается
так ничего и там, где список процессов недоступен (Windows): долгую сборку там
не отличить от ожидания.

**Stop** отправляет Ctrl-C всему, что запустил Codex, а потом самому Codex,
как и для Claude Code. Каждую команду Codex запускает в своей группе
процессов, куда сигнал группе самого Codex не дошёл бы; страница находит
каждую по процессу, который её запустил.

**Когда он закончил**, страница читает события Codex: его последнее сообщение,
сколько токенов он потратил и в чём ему отказала песочница или отказал сам
Codex — это видно только как неудачная команда, потому что код выхода и тогда
0. Как бы он ни закончил, страница перечисляет файлы, которые он изменил вне
разрешённых папок, — изменённые, новые или удалённые, — или говорит, что
таких нет. В `.echolot/` и папки, которые пишут сборка и IDE (`build/`,
`.gradle/`, `.idea/`), страница не смотрит. Файл, который вы сами измените,
пока он работает, тоже попадёт в список; изменённый после конца — нет.

Одновременно работает что-то одно: проверка и агент не идут вместе ни в каком
порядке. Пока агент работает, стартовая страница говорит об этом над кнопкой,
а кнопка — почему ждёт; пока идёт проверка, об этом говорит **Dig deeper**. С
выключенным JavaScript каждый шаг — обычная форма: отчёт показывает проверки
списком с галочками, а страница агента сама обновляется каждые пять секунд.

## На что сервер отвечает и в чём отказывает

Это HTTP-сервер из стандартной библиотеки Python, спроектированный так, чтобы
отвечать только открытой им странице:

- Слушает только `127.0.0.1`. Запрос с любым другим `Host` отклоняется.
- При каждом старте генерируется случайный токен, входящий в путь URL и во
  все ссылки. Запрос без токена отклоняется. Токен не хранится в cookie (чтобы
  не утекать на другие порты `127.0.0.1`). После остановки сервера токен
  перестаёт действовать.
- Все изменяющие запросы (POST-формы запуска, Stop, **Set it up**, **Set the
  limit**, **Look in this folder** и **Read them**, а также запросы агента: экран перед запуском, для любого из двух,
  **Start**, его **Stop**, **Take the markers out** и **Close the
  investigation**) должны приходить со страниц самого сервера
  (`Origin`/`Referer` проверяются).
- Размер тела формы ограничен 4096 байтами; запросы без длины, сверх лимита
  или оборванные отклоняются без чтения. Одно поле формы — путь: папка, в
  которую смотрит **Analyse trace files** (см. ниже). Остальные данные формы не
  подставляются в пути или команды: сценарий должен существовать в конфиге,
  число запусков — целое от 1 до 20, лимит — число от 0.1 до 60, отмеченная
  проверка — одна из проверок отчёта на диске, которая что-то нашла, а
  настройка создаёт исключительно `echolot.yml` в папке проекта. **Set the
  limit** меняет только этот же файл, одну его строку, а сценарий, который
  оно называет, должен быть в конфиге. То, каким страница
  видела файл, передаётся двумя контрольными суммами: их только сравнивают с
  файлом и никогда не используют как путь. Агент, названный в адресе, — один
  из тех, кого страница запускает: Claude Code или Codex. Командную строку
  агента сервер собирает только из конфига и отчёта.
- Отдаёт только сгенерированные HTML-страницы и ни одного файла с диска.
- Папка, которую называет **Analyse trace files**, — единственный путь в
  запросе, и файла странице она не даёт. Сервер смотрит в неё на один уровень
  вглубь и берёт только имена, размеры и время файлов, имена которых кончаются
  на `.perfetto-trace`, `.pftrace` или `.trace`, и сколько таких файлов в
  каждой вложенной папке. Ни один из них он не открывает: выбранные записи
  уходят в `analyze` по путям, а отчёт пишется в `.echolot/out/elsewhere`
  проекта и никогда — в названную папку. Путь — текст не длиннее 512 символов
  без управляющих символов; `~` — домашняя папка, относительный путь берётся
  от папки проекта. Страница чужого сайта назвать папку не может: у неё нет ни
  токена, ни нужного `Origin`, как и для любого другого нажатия.
- Адрес, на который отправляется форма, — не страница. Если его прочитать
  (перезагрузить то, что нарисовало нажатие, или вернуться туда по истории),
  он ничего не запускает и отправляет браузер туда, где это нажатие делается:
  экран перед запуском агента — обратно к его отчёту, где **Dig deeper**
  нажимают снова; **Stop**, **Take the markers out** и **Close the
  investigation** — к ответу агента; остальное — на стартовую страницу.
- Строгий `Content-Security-Policy`: страницы не загружают внешних шрифтов,
  скриптов или картинок. Страница с живого сервера может только отправлять
  формы обратно на свой адрес и опрашивать статус прогона; сохранённые на диск
  HTML-отчёты не имеют даже этого.

Два экземпляра `echolot ui` не мешают друг другу: у каждого свой порт и свой
токен.

## Что записывается на диск

Просмотр страниц не пишет ничего, просмотр папки тоже. Запуск проверки и
**Read them** создают файлы под `.echolot/`:

| файл | что это |
|---|---|
| `.echolot/log/check.json` | последняя проверка: процесс, состояние и код возврата каждой команды, итог |
| `.echolot/log/check.collect.log`, `check.analyze.log`, `check.compare.log` | вывод каждой команды в том виде, как она его печатала |
| `.echolot/log/check.stop` | флаг запроса остановки на время завершения |
| `before.json` рядом с отчётом | копия предыдущего отчёта перед **Check again** для `compare` |
| `comparison.html` рядом с отчётом | страница сравнения для вкладки **After the fix** |
| `.echolot/out/elsewhere/` | отчёт по записям из сторонней папки: `report.json`, `report.md` и `report.html`, как их пишет `analyze -o`; следующая прочитанная папка пишет поверх |

**Dig deeper** пишет то, что пишут две его команды: `echolot hunt` открывает
расследование (`.echolot/hunt.json`, трейсы отчёта откладываются в
`.echolot/traces/`), а агент меняет код — Claude Code только в разрешённых
папках — и пишет `.echolot/verdict.json`. Codex к тому же сам отмечает проект
как доверенный в ваших `~/.codex/config.toml`. Собственные файлы страницы —
это сам запуск:

| файл | что это |
|---|---|
| `.echolot/log/dig.json` | последний агент, запущенный страницей: процесс, командная строка, расследование, итог |
| `.echolot/log/dig.agent.log` | что напечатал агент: у Claude Code один JSON-объект в конце работы, у Codex события, по JSON-объекту на строку, по мере работы |
| `.echolot/log/dig.files.json` | для Codex: файлы проекта перед запуском, размер и время у каждого, для списка того, что он изменил |
| `.echolot/log/dig.stop` | флаг запроса остановки на время завершения |

**Set it up** один раз пишет в проект:

| файл | что это |
|---|---|
| `echolot.yml` | конфиг от `echolot scan`, создаётся только с нуля и не перезаписывается |
| файлы `echolot init` | слой для агента, строки в `.gitignore`, `.echolot/hosts.json` (если ещё не было) |
| `.echolot/log/setup.json`, `setup.init.log` | состояние и лог запуска `init` |

**Set the limit** пишет один файл, `echolot.yml`, и в нём одну строку — строку
`budget_ms` сценария или эту строку, добавленную там, где её не было. Больше
ничего не пишется, и рядом не
остаётся даже временного файла.

Сами команды пишут свои обычные артефакты: трейсы, отчёты, сравнения и строки
в `.echolot/log/runs.jsonl`. При остановке сервер оставляет свою строку в
журнале запусков; `ECHOLOT_NO_RECORD=1` отключает журнал.
